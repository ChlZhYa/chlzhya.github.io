# 写作闭环与卡片可读性

## 当前结构

`app.js` 从 `flow-journal-v1` 读取 `{version:1, entries:Entry[]}`，与单独的只读示例合并后渲染。`flow-model.js` 只负责日期、分类和筛选。新建表单仅存在 DOM 中，关闭后仍在，刷新即丢失。保存会先读最新快照，但读写之间没有跨标签页互斥；导出使用内存中的旧快照。没有修改入口。记录达到 10,000 条后仍可新增，下一次读取却拒绝 10,001 条。

## 使用目标

写下念头，暂时关掉窗口，重新打开或刷新同一标签页后继续。打开自己的记录可以修改。修改期间另一标签页已保存同一记录时，保留输入，拒绝覆盖，并提供另存新记录。其他记录的更改可合并。示例仍只读。

## 候选与选择

候选 A 保持浏览器适配在 app.js，增加单标签页 sessionStorage 草稿、Web Locks 写锁和修改基线。候选 B 将快照规则抽成纯模块，也考虑持久草稿和导入；指出容量边界与过期导出问题。选择 A 的生命周期和 B 的小型纯快照边界。不引入完整 workspace controller、数据库迁移或导入流程。它们扩大状态和恢复政策，超出这轮最需要打磨的核心流程。

以 1 到 3 分比较。兼容现有数据 A3/B3；避免误覆盖 A3/B2（B 的读后写仍有竞态）；复杂度 A3/B2；可测试性 A2/B3。综合保留原快照，抽出规则，串行写入。此判断由 root 基于两份只读架构报告作出，代码评审会再次检查。

## 数据和接口约定

Entry 保持原字段和 version1。新增纯模块 `entry-model.js`，集中有效记录/快照、容量、创建/修改合并和基线冲突规则。浏览器存储和 DOM 留在 app.js。

WriterSession 是 `{mode:'create', touched, draft}` 或 `{mode:'edit', touched, id, baseline, draft}`。touched 表示是否实际输入过，避免仅打开空窗口就阻挡后续修改。draft 保存原始表单字符串（包括未完成的标题/日期/标签），不复用完整 Entry 验证。baseline 保存原记录全部语义字段，不能只比较 updatedAt。草稿独立使用 sessionStorage 的版本键，不写入正式记录。刷新可以恢复此标签页；关闭标签页或清站点数据不承诺恢复，界面和文档明确说明。

保存通过 `navigator.locks.request` 包住读取最新快照、合并、容量检查和写入。缺少 Web Locks 的环境拒绝写入并保留输入，提供可操作的说明。校验/冲突/配额错误均不清理草稿、不关闭窗口。修改成功保留 id；只有明确另存才生成新 id。编辑已在其他标签页改变或不存在的记录不能静默复活/覆盖。保存成功后才清草稿，再同步视图。

导出重新读取最新有效快照。创建与修改都不能产生超出 10,000 条或重复 id 的快照。没有删除操作，不改写示例。

## 视图约定

卡片增加正文摘要，避免重复自动标题第一行，最多三行。继续保留错落位置和颜色，增加摘要后检查卡片之间、日历和介绍之间的边界。Writer 使用“稍后继续”和草稿状态，编辑使用清晰标题和保存修改。错误处可另存保住输入。控制数量以现有原生 dialog 为限。

## 验证

纯测试覆盖原快照兼容、非法数据拒绝、容量边界、保留其他记录、修改不复制、全字段冲突。真实浏览器覆盖同标签页刷新恢复、新建/编辑/另存、搜索导出、双标签页串行保存与冲突、390px 和桌面布局。不得把语法检查说成浏览器验证。
